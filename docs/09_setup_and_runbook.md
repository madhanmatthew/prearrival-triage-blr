## 4. RL specification (Component 3) `[DECISION]`

| Element | Spec |
|---|---|
| Control scheme | **One agent controlling all 4 junctions jointly** (Stable-Baselines3 has no native multi-agent). Actions: each junction chooses `main_green` or `cross_green` → **2⁴ = 16 discrete actions** |
| Step timing | `delta_time = 5 s` between decisions, `min_green = 10 s`, `yellow = 3 s` |
| Observation (custom `ObservationFunction`) | Per junction: normalised queue length on main-approach lanes, on cross-approach lanes, current phase one-hot, `ambulance_within_1km` flag, ambulance distance to junction normalised by 1000 m (1.0 if none). Total 4 × (2 + 2 + 1 + 1) = 24 dims |
| Reward (custom `reward_fn`) | `r = − w_amb · ambulance_wait_step − w_gen · mean_waiting_time_others − w_cross · max_cross_queue_penalty` with `w_amb=1.0`, `w_gen=0.1`, `w_cross=0.05` (initial; tune on validation demand, log every value tried) |
| Algorithm | DQN first (`MlpPolicy`, discrete actions); PPO as second run if time |
| Training budget | 100k timesteps per seed initially; ≥3 seeds; eval every 1000 steps × 5 episodes, deterministic |
| Baselines | (a) SUMO default fixed-time, (b) "always green for ambulance" naive preemption. Report all three |
| Metrics | Ambulance transit time (mean ± std over ≥20 eval episodes per demand level); mean general waiting time; throughput; max cross-street queue |
| Known risk | Junctions are 5–6 km apart, so coupling between them is weak and gains may be modest versus the ~73% figure in dense-network literature. Report honestly; optionally add a compressed-spacing variant (e.g., 500 m) as a secondary experiment, clearly labelled. Also note ambulance-aware obs/reward must be custom-built; `sumo-rl` defaults only see queue/density |

## 6. Demo flow (final presentation) `[DECISION]`

**Scenario:** road accident near Silk Board, two injured, one with heavy bleeding.
1. User opens the web page, speaks a report in Kannada (Whisper transcribes; show transcript).
2. Dialogue asks 3–4 targeted questions (conscious? bleeding? breathing?) → severity vector shown.
3. Guidance panel shows first-aid steps **with source chunk citations** and a "grounded ✓" badge.
4. Coordinator assigns ambulance; map shows route via ORR.
5. Vitals replay (from a held-out MIMIC patient, compressed timeline) streams in; fused risk score and trend gauge update live; SHAP/IG explanation shown for the latest step.
6. Hospital panel: ranked hospitals with score breakdown; toggle blood-need to show the pick changing.
7. SUMO replay: fixed-time vs RL-controlled corridor side by side with ambulance transit times.
8. Police dashboard receives alert (units, perimeter, route).
9. Final slide: benchmark table (naive vs AI dispatch, 8+2 scenarios) and limitations.

**Fallbacks if live parts fail:** pre-recorded audio, cached LLM responses, pre-rendered SUMO video/gif.
